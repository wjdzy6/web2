[Opening - ~30 seconds]

"Hi everyone, my name is [your name], and today I'll be demonstrating my
Assignment 2 project for PROG2002 Web Development II. The project is called

In this video I'll cover three main areas: first, the database and API

================================================================================
PART 1: Database and API architecture (ULO3: Plan & design)  [~4 minutes]
================================================================================

"Let's start with the backend architecture. The system has three layers:
a MySQL database, a Node.js and Express.js RESTful API server, and a
client-side website built with HTML, CSS, and vanilla JavaScript."

[Open database/schema.sql in the editor]

"Here is the database schema. I designed two tables with a one-to-many
relationship.

The first table is 'categories'. It has an auto-incrementing id as the
primary key, and a unique name field. It stores the different types of
charity events, like Gala Dinner, Fun Run, Concert, and so on.

The second table is 'events'. This is the main table. Let me walk through
the key fields:
- id: primary key
- name, description, full_description, purpose: textual information about
  the event
- event_date and event_time: when the event takes place
- location: the venue
- category_id: a foreign key that links to the categories table. This
  creates the one-to-many relationship - one category can have many events.
- image: a URL to the event image
- ticket_price and is_free: pricing information
- goal_amount and raised_amount: used for the fundraising progress display
- is_suspended: a flag to hide events that violate policy

The foreign key is set with ON DELETE CASCADE, so if a category is removed,
its events are removed too.

I populated the database with 6 categories and 11 sample events, including
one event that has already passed, so I can demonstrate the Past/Upcoming
status logic."

[Open event_db.js]

"This is event_db.js, the database connection file. I used the mysql2
library with a connection pool instead of a single connection, which is
more efficient for handling multiple requests. The pool connects to the
charity_event_db database on localhost."

[Open server.js]

"Now for the API. The server is built with Express.js and exposes four
GET endpoints. I only used GET methods because this assessment focuses on
data retrieval - POST, PUT, and DELETE will be added in Assessment 3.

The first endpoint is GET /api/categories. It simply returns all
categories from the database. This is used to populate the category
dropdown on the search page.

The second endpoint is GET /api/events/home. It returns all non-suspended
events, joined with their category name, ordered by event date. This
powers the home page listing.

The third endpoint is GET /api/events/search. This one is interesting -
it accepts three optional query parameters: date, location, and category.
The server builds the SQL query dynamically, only adding WHERE clauses
for the parameters that are actually provided. The location uses a LIKE
wildcard for partial matching. All user inputs use parameterised queries
to prevent SQL injection.

The fourth endpoint is GET /api/events/:id. It takes an event ID from the
URL and returns the full details of that single event. If the event
doesn't exist, it returns a 404 response.

Let me test the search endpoint using the browser to show it works."

[Open browser, go to http://localhost:3000/api/events/search?location=Sydney]

"You can see the API returns a JSON object with a success flag and a data
array containing the 4 events located in Sydney. Each event object
includes all the fields plus the category_name joined from the categories
table."

PART 2: Data flow and interaction (ULO1: Apply & ULO3: Develop)  [~4 minutes]
================================================================================

"Now let me explain the data flow between the API and the website, using
the search page as an example."

[Open public/js/search.js]

"The process starts when the user submits the search form. I attached a
submit event listener to the form that calls the searchEvents function.

Inside searchEvents, I first read the values from the three form fields:
date, location, and category. Then I build a URLSearchParams object, only
appending the parameters that have values.

Next, I use the Fetch API to send a GET request to
/api/events/search with those query parameters. The fetch returns a
Promise. I parse the response as JSON, then take the data array.

For each event in the results, I call renderEventCard, which generates an
HTML string for an event card. I then set the innerHTML of the results
container to join all the card strings together. This is the DOM
manipulation step that displays the data on the page.

If the fetch fails or the response indicates an error, I catch it and
display an error message by manipulating the DOM - specifically, I add a
'show' class to the error message element.

Let me also show the event detail page, which uses a URL query string to
pass the event ID between pages."

[Open public/js/event.js]

"On the home page or search page, each event card has a link that points to
event.html?id= followed by the event ID. When the detail page loads, I use
URLSearchParams to read the 'id' parameter from window.location.search.

Then I fetch /api/events/ with that ID, get the response, and call
renderEvent to display all the details - the name, date, location, full
description, purpose, and a fundraising progress bar that's calculated
from raised_amount divided by goal_amount.

The Register button has a click listener that opens a modal dialog saying
'This feature is currently under construction,' which is what the
assignment requires for this stage."

PART 3: Website functionality demo (ULO3)  [~5 minutes]
================================================================================

"Now let me do a live walkthrough of the website."

[Open http://localhost:3000/]

"This is the Home page. At the top there's a hero section with the
organisation name and mission statement. Below that is a stats section,
and then the dynamic event listing.

Each event is displayed as a card with an image, category badge, name,
short description, date, location, and ticket price. You can see that the
'Summer Beach Clean-Up 2026' event has a red 'Past' badge because its date
is before today, while all the others have a green 'Upcoming' badge. The
status is determined in JavaScript by comparing the event date to the
current date.

Each card has a 'View Details' button."

[Click on an event card's View Details button]

"This takes us to the Event Detail page. The URL contains ?id=1, which
the JavaScript reads to fetch the correct event.

Here you can see the full event information: the image, complete
description, the purpose, and a fundraising progress bar showing how much
has been raised towards the goal. The sidebar shows the date, time,
location, category, ticket price, and goal amount.

If I click the Register Now button, a modal appears saying 'This feature
is currently under construction.' I can close it by clicking OK or
clicking outside the modal."

[Click back to Home, then navigate to Search]

"Now let's go to the Search Events page. When the page first loads, it
automatically loads all events. The category dropdown is populated from
the /api/categories endpoint.

Let me filter by location. I'll type 'Sydney' and click Search."

[Type Sydney, click Search]

"The page now shows only the 4 events in Sydney. The result count is
displayed above the listing, and each result links to its detail page.

Let me also filter by category. I'll select 'Gala Dinner' and search
again."

[Select Gala Dinner, click Search]

"Now it shows only the Gala Dinner events. Let me add a date filter too."

[Add a date, search]

"And now the results are filtered by both category and date, demonstrating
that multiple criteria can be combined.

Finally, let me click 'Clear Filters' to reset all form fields and reload
the full list."

[Click Clear Filters]

"The form is reset and all events are shown again.

Let me also demonstrate error handling. If I stop the server and try to
search, the page displays a clear error message instead of crashing."

[Optional: stop server, show error]
